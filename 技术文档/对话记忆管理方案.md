# 对话记忆管理方案

## 一、核心思想

采用 **"摘要列表 + 滑动窗口"** 的混合方案，通过以下策略降低 Token 消耗：

1. **摘要列表**：维护最近 5 条摘要，每条摘要对应一段历史对话
2. **滑动窗口**：保留最近 10 条完整消息
3. **固定窗口**：摘要列表达到上限时，直接丢弃最旧的摘要，不进行合并或压缩
4. **智能触发**：每新增 10 条消息，生成 1 条新摘要

## 二、技术架构

### 核心组件

```
┌─────────────────────────────────────────────────────────┐
│                  MessageMemoryAdvisor                      │
│  - 控制上下文组装逻辑                                       │
│  - 触发摘要生成                                            │
│  - 管理消息裁剪                                            │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                   RedisChatMemory                         │
│  - 存储对话消息（Redis List）                              │
│  - 存储摘要列表（Redis List）                              │
│  - 存储消息计数器（Redis String）                          │
└─────────────────────────────────────────────────────────┘
```

### 数据结构

```java
// Redis存储结构
1. 对话消息：chat:memory:{conversationId}
   - 类型：List
   - 内容：序列化的Message对象
   - 限制：最多20条（RedisChatMemory中的LIMIT_MESSAGES）

2. 摘要列表：chat:summary:list:{conversationId}
   - 类型：List
   - 内容：摘要字符串
   - 限制：最多5条

3. 消息计数器：chat:message:count:{conversationId}
   - 类型：String
   - 内容：消息总数
   - 用途：判断是否需要生成新摘要

4. 上次摘要生成时的消息数：chat:message:count:{conversationId}:last_summary
   - 类型：String
   - 内容：上次生成摘要时的消息总数
   - 用途：与当前消息计数对比，判断是否达到摘要更新间隔
```

## 三、工作流程

### 1. 请求处理流程（before 方法）

```java
public ChatClientRequest before(ChatClientRequest chatClientRequest, AdvisorChain advisorChain) {
    String conversationId = getConversationId(chatClientRequest.context(), defaultConversationId);
    List<Message> memoryMessages = chatMemory.get(conversationId);
    List<Message> processedMessages = new ArrayList(memoryMessages);

    // 步骤1：检查是否查询到短期记忆
    if (processedMessages == null || processedMessages.size() == 0) {
        log.info("会话id：{}，未查询到短期记忆", conversationId);
    }
    log.info("会话id：{}，查询到短期记忆{}条", conversationId, processedMessages.size());

    // 步骤2：检查是否需要裁剪
    if (processedMessages.size() > maxContextMessages) {
        // 步骤3：判断是否启用摘要功能
        if (enableSummary && processedMessages.size() > summaryThreshold) {
            // 步骤4：从Redis获取摘要列表
            List<String> summaryList = null;
            if (chatMemory instanceof RedisChatMemory) {
                RedisChatMemory redisChatMemory = (RedisChatMemory) chatMemory;
                summaryList = redisChatMemory.getSummaryList(conversationId);
            }

            // 步骤5：提取最近消息
            List<Message> recentMessages = processedMessages.subList(
                processedMessages.size() - summaryThreshold,
                processedMessages.size()
            );

            // 步骤6：组装上下文（摘要列表 + 最近消息）
            processedMessages = new ArrayList<>();

            if (summaryList != null && !summaryList.isEmpty()) {
                String combinedSummary = String.join("\n\n", summaryList);
                Message summaryMessage = new SystemMessage("历史对话摘要：\n" + combinedSummary);
                processedMessages.add(summaryMessage);
                log.info("会话id：{}，使用{}条摘要", conversationId, summaryList.size());
            }

            processedMessages.addAll(recentMessages);
            log.info("会话id：{}，上下文已组装为：{}条摘要 + {}条最近消息",
                conversationId, summaryList != null ? summaryList.size() : 0, recentMessages.size());
        } else {
            // 步骤7：纯滑动窗口裁剪
            processedMessages = processedMessages.subList(
                processedMessages.size() - maxContextMessages,
                processedMessages.size()
            );
            log.info("会话id：{}，已裁剪至最近{}条消息", conversationId, maxContextMessages);
        }
    }

    // 步骤8：添加当前请求的指令消息
    processedMessages.addAll(chatClientRequest.prompt().getInstructions());

    // 步骤9：构建处理后的请求
    ChatClientRequest processedChatClientRequest = chatClientRequest.mutate()
        .prompt(chatClientRequest.prompt().mutate().messages(processedMessages).build())
        .build();

    // 步骤10：保存用户消息到记忆
    UserMessage userMessage = processedChatClientRequest.prompt().getUserMessage();
    chatMemory.add(conversationId, userMessage);

    return processedChatClientRequest;
}
```

### 2. 响应处理流程（after 方法）

```java
public ChatClientResponse after(ChatClientResponse chatClientResponse, AdvisorChain advisorChain) {
    // 步骤1：提取助手回复消息
    List<AssistantMessage> assistantMessages = new ArrayList();
    if (chatClientResponse.chatResponse() != null) {
        assistantMessages = chatClientResponse.chatResponse().getResults().stream()
            .map(g -> g.getOutput())
            .toList();
    }

    // 步骤2：获取对话ID
    String conversationId = getConversationId(chatClientResponse.context(), defaultConversationId);

    // 步骤3：保存助手回复到记忆
    chatMemory.add(conversationId, assistantMessages);

    // 步骤4：判断是否启用摘要功能
    if (enableSummary && chatMemory instanceof RedisChatMemory) {
        RedisChatMemory redisChatMemory = (RedisChatMemory) chatMemory;

        // 步骤5：获取消息计数
        long messageCount = redisChatMemory.getMessageCount(conversationId);
        long lastSummaryMessageCount = redisChatMemory.getLastSummaryMessageCount(conversationId);

        // 步骤6：判断是否需要生成新摘要
        if (messageCount - lastSummaryMessageCount >= summaryUpdateInterval) {
            // 步骤7：获取对话历史
            List<Message> memoryMessages = chatMemory.get(conversationId);

            if (memoryMessages.size() > summaryThreshold) {
                // 步骤8：提取需要摘要的消息（最近N条）
                List<Message> messagesToSummarize = memoryMessages.subList(
                    Math.max(0, memoryMessages.size() - summaryUpdateInterval),
                    memoryMessages.size()
                );

                // 步骤9：生成新摘要（包含降级策略）
                log.info("会话id：{}，开始生成摘要，基于{}条消息",
                    conversationId, messagesToSummarize.size());
                String summary = generateSummary(messagesToSummarize);

                // 步骤10：处理摘要生成结果
                if (summary != null) {
                    // 摘要生成成功，添加到列表
                    redisChatMemory.addSummaryToList(conversationId, summary, maxSummaries);
                    redisChatMemory.updateLastSummaryMessageCount(conversationId, messageCount);
                    log.info("会话id：{}，摘要已生成并保存", conversationId);
                } else {
                    // 摘要生成失败，自动回退到纯滑动窗口模式
                    log.warn("会话id：{}，摘要生成失败，将回退到纯滑动窗口模式", conversationId);
                }
            }
        }
    }

    return chatClientResponse;
}
```

### 3. 摘要生成流程（包含降级策略）

```java
private String generateSummary(List<Message> messages) {
    try {
        // 步骤1：将消息列表转换为文本
        String conversationText = messages.stream()
            .map(msg -> {
                String role = msg.getMessageType().name();
                String content = msg.getText();
                return String.format("[%s]: %s", role, content);
            })
            .collect(Collectors.joining("\n"));

        // 步骤2：构建摘要生成提示词
        String prompt = String.format(
            "请将以下对话历史压缩成简洁的摘要，保留关键信息、重要决策和上下文。摘要应该清晰、简洁，便于后续对话理解：\n\n%s\n\n摘要：",
            conversationText
        );

        // 步骤3：调用大模型生成摘要
        return summaryChatClient.prompt()
            .user(prompt)
            .call()
            .content();
    } catch (Exception e) {
        // 步骤4：异常处理，返回null触发降级策略
        log.error("摘要生成失败，将回退到纯滑动窗口模式。错误信息：{}", e.getMessage());
        return null;
    }
}
```

### 4. 摘要列表管理流程

```java
public void addSummaryToList(String conversationId, String newSummary, int maxSummaries) {
    String key = SUMMARY_LIST_KEY_PREFIX + conversationId;

    // 步骤1：获取现有摘要列表
    List<String> summaries = getSummaryList(conversationId);

    // 步骤2：添加新摘要
    summaries.add(newSummary);

    // 步骤3：如果超过上限，直接丢弃最旧的摘要
    while (summaries.size() > maxSummaries) {
        summaries.remove(0);
        log.info("会话id：{}，已丢弃最旧的摘要", conversationId);
    }

    // 步骤4：保存到Redis
    redisTemplate.delete(key);
    redisTemplate.opsForList().rightPushAll(key, summaries);
    redisTemplate.expire(key, 7, TimeUnit.DAYS);

    log.info("会话id：{}，当前摘要数量：{}", conversationId, summaries.size());
}

public List<String> getSummaryList(String conversationId) {
    String key = SUMMARY_LIST_KEY_PREFIX + conversationId;
    Long size = redisTemplate.opsForList().size(key);

    // 如果列表为空，返回空列表
    if (size == null || size == 0) {
        return new ArrayList<>();
    }

    // 从Redis获取摘要列表
    List<Object> objects = redisTemplate.opsForList().range(key, 0, -1);
    return objects.stream()
        .map(Object::toString)
        .collect(Collectors.toList());
}
```

### 5. 消息计数器管理流程

```java
public long incrementMessageCount(String conversationId) {
    String key = MESSAGE_COUNT_KEY_PREFIX + conversationId;
    Long count = redisTemplate.opsForValue().increment(key);
    redisTemplate.expire(key, 7, TimeUnit.DAYS);
    log.debug("会话id：{}，消息计数：{}", conversationId, count);
    return count != null ? count : 1L;
}

public long getMessageCount(String conversationId) {
    String key = MESSAGE_COUNT_KEY_PREFIX + conversationId;
    Object count = redisTemplate.opsForValue().get(key);
    return count != null ? Long.parseLong(count.toString()) : 0L;
}

public long getLastSummaryMessageCount(String conversationId) {
    String key = MESSAGE_COUNT_KEY_PREFIX + conversationId + ":last_summary";
    Object count = redisTemplate.opsForValue().get(key);
    return count != null ? Long.parseLong(count.toString()) : 0L;
}

public void updateLastSummaryMessageCount(String conversationId, long count) {
    String key = MESSAGE_COUNT_KEY_PREFIX + conversationId + ":last_summary";
    redisTemplate.opsForValue().set(key, count, 7, TimeUnit.DAYS);
    log.debug("会话id：{}，上次摘要生成时的消息数已更新为：{}", conversationId, count);
}
```

### 6. 降级策略说明

当摘要生成失败时，系统会自动触发降级策略：

1. **触发条件**：

   - 摘要生成过程中发生异常（网络错误、API 限流、模型错误等）
   - `generateSummary()` 方法返回 `null`

2. **降级行为**：

   - 在 `before` 方法中：如果摘要列表为空或获取失败，自动使用纯滑动窗口模式
   - 在 `after` 方法中：如果摘要生成失败，记录警告日志，下次请求继续使用纯滑动窗口模式

3. **恢复机制**：

   - 下次摘要生成成功后，自动恢复正常模式
   - 无需手动干预，系统自动恢复

4. **日志记录**：
   - 失败时记录错误日志：`摘要生成失败，将回退到纯滑动窗口模式。错误信息：{错误详情}`
   - 成功时记录信息日志：`会话id：{id}，摘要已生成并保存`

## 五、成本分析

### 场景：对话进行到 100 条消息

#### 纯滑动窗口方案（对比基准）

```
上下文Token消耗：
- 50条历史消息 × 50 tokens/条 = 2500 tokens
- 当前请求 = 100 tokens
总计：2600 tokens/次
```

#### 摘要列表 + 滑动窗口方案

```
摘要生成成本（一次性）：
- 生成次数：100条消息 ÷ 10条/次 = 10次
- 每次生成：500 tokens
总计：10 × 500 = 5000 tokens

上下文Token消耗：
- 5条摘要 × 200 tokens/条 = 1000 tokens
- 10条最近消息 × 50 tokens/条 = 500 tokens
- 当前请求 = 100 tokens
总计：1600 tokens/次

节省：2600 - 1600 = 1000 tokens/次
```

#### 收益分析

```
假设每天对话1000次，平均每次对话20轮：

纯滑动窗口：
- Token消耗：1000 × 2600 = 2,600,000 tokens/天

摘要列表方案：
- 摘要生成成本：1000 × (20÷10) × 500 = 1,000,000 tokens/天
- 上下文Token消耗：1000 × 1600 = 1,600,000 tokens/天
- 总计：2,600,000 tokens/天

结论：在对话轮数较少时，成本相当
      在对话轮数较多（>20轮）时，开始节省成本
```

## 六、优势

1. **降低 Token 消耗**：通过摘要压缩历史信息，减少上下文长度
2. **保留时间维度**：多条摘要反映对话的不同阶段，便于理解对话脉络
3. **逻辑简单**：固定窗口 + 直接丢弃，易于理解和维护
4. **可控性强**：通过参数灵活控制摘要数量、更新频率等
5. **避免信息累加**：直接丢弃最旧的摘要，不会导致摘要无限增长

## 七、劣势

1. **信息丢失**：丢弃的摘要可能包含重要信息，导致上下文不完整
2. **依赖 LLM 能力**：摘要质量完全依赖 LLM 的生成能力
3. **额外成本**：需要调用 LLM 生成摘要，增加 Token 消耗
4. **时效性问题**：摘要生成后，如果对话继续发展，旧摘要可能不再准确
5. **Redis 依赖**：依赖 Redis 存储摘要列表，存在数据丢失风险

## 八、适用场景

**适合：**

- 对话主题相对独立，早期信息对后续影响不大
- 对话轮数较多（>20 轮），Token 消耗成为主要问题
- 对上下文完整性要求不高的场景

**不适合：**

- 需要长期上下文的复杂对话
- 对信息完整性要求极高的场景
- 对话轮数较少（<10 轮），摘要生成成本高于节省的 Token

## 九、未来优化方向

1. **智能摘要触发**：基于话题变化、重要程度等智能判断是否需要生成摘要
2. **摘要质量评估**：使用另一个 LLM 验证摘要质量，确保关键信息不丢失
3. **分层摘要**：实现不同粒度的摘要（详细、中等、简略），根据需求选择
4. **摘要缓存优化**：优化 Redis 存储结构，提高查询效率
5. **降级策略**：摘要生成失败时，自动回退到纯滑动窗口模式
